# Управление панелями через MCP

Каждая панель VibeTerm - отдельный PowerShell в общем окне. Здесь описано, как управлять любой из них из редактора.

Пока окно открыто, приложение слушает локальный программный интерфейс. Отдельная программа `VibeTerm.Mcp` переводит вызовы MCP в запросы к этому окну.

MCP (Model Context Protocol) - способ, которым редактор вызывает внешние инструменты: открыть панель, напечатать команду, прочитать вывод.

## Что должно быть запущено

1. Сначала откройте VibeTerm. Без окна управлять нечем: процессы панелей живут внутри приложения.
2. Флажок `Enable local panel API for MCP` в окне Settings включает интерфейс. Изменение действует со следующего запуска. По умолчанию флажок включён.
3. Затем подключите `VibeTerm.Mcp` в редакторе.

Интерфейс слушает только `127.0.0.1`. С другого компьютера к нему не подключиться.

Адрес и ключ доступа записываются в файл:

```text
%APPDATA%\VibeTerm\panel-api.json
```

Пример содержимого:

```json
{
  "baseUrl": "http://127.0.0.1:54321",
  "token": "ключ",
  "pid": 1234
}
```

Файл появляется при открытии окна и удаляется при выходе, если в нём всё ещё указан этот процесс. Ключ позволяет печатать команды в ваших панелях. Не отправляйте файл другим людям.

Если переменная среды `VIBETERM_PANEL_API_FILE` задана и у приложения, и у `VibeTerm.Mcp`, оба используют этот путь вместо файла в `%APPDATA%`. Так удобно запускать проверку, не задевая обычный файл.

Если открыто несколько окон, в файле остаётся адрес последнего. Редактор обращается к нему.

## Подключение в Cursor

Соберите сервер:

```powershell
dotnet build .\VibeTerm.Mcp\VibeTerm.Mcp.csproj -c Release
```

Пользовательский файл настроек, общий для всех проектов:

```text
%USERPROFILE%\.cursor\mcp.json
```

Если `dotnet` не находится по имени, в `command` нужен полный путь к `dotnet.exe`. `timeout` больше минуты нужен потому, что `ask_agent` может ждать ответ модели до двух минут.

```json
{
  "mcpServers": {
    "vibeterm": {
      "command": "C:\\Users\\Имя\\AppData\\Local\\Microsoft\\dotnet\\dotnet.exe",
      "args": [
        "F:\\!yarik\\VibeTerm\\VibeTerm.Mcp\\bin\\Release\\net7.0\\VibeTerm.Mcp.dll"
      ],
      "timeout": 120000
    }
  }
}
```

После правки файла перезапустите Cursor или обновите список MCP в настройках. Сервер сам не открывает окно и не запускает агентов командной строки.

Журнал сервера не пишется в стандартный вывод: по нему идёт протокол MCP.

## Инструменты

Номер панели берётся из `list_panels`. Это поле `id`, а не порядковый номер на экране. Порядковый номер лежит в поле `index`.

| Инструмент | Что делает |
| --- | --- |
| `list_panels` | Список панелей: имя, статус, каталог, смещение вывода |
| `get_panel` | Одна панель по `panelId` |
| `create_panel` | Новая панель. `name` и `workingDirectory` можно не передавать. Каталог, если он передан, должен существовать |
| `close_panel` | Закрывает панель и останавливает её оболочку |
| `select_panel` | Выбирает панель и переводит в неё фокус клавиатуры |
| `rename_panel` | Меняет имя в боковой панели |
| `send_input` | Печатает текст. `submit` по умолчанию `true`: после текста нажимается Enter |
| `send_keys` | Одна клавиша: `enter`, `tab`, `escape`, `backspace`, `delete`, `up`, `down`, `left`, `right`, `home`, `end`, `pageup`, `pagedown`, `space`, `ctrl+c`, `ctrl+d`, `ctrl+z`, `ctrl+l` |
| `read_output` | Текст вывода. В следующий вызов передайте прежний `nextOffset` как `since` |
| `wait_for_text` | Ждёт точную строку в новом выводе. Предел ожидания - 30 секунд |
| `list_agents` | Панели уже открытого окна и догадка, кто в панели: `claude`, `codex` или `shell` |
| `ask_agent` | Печатает задание в панель, где агент уже запущен, и возвращает новый вывод |
| `ask_agents` | То же задание сразу нескольким панелям. Сбой одной не отменяет остальные |

Сразу после `create_panel` поле `ready` может быть `false`, а статус - `starting`. Оболочка ещё запускается. `send_input` в этот момент вернёт ошибку. Дождитесь `ready: true` или появления приглашения через `wait_for_text`.

`read_output` возвращает текст текущего процесса. Цветовые коды убраны. Возврат каретки и стирание до конца строки применяются к текущей строке, поэтому приглашение PowerShell остаётся читаемым. Программы на весь экран, например редактор, будут читаться плохо: курсор вверх не переписывает уже сохранённые строки.

Старый текст хранится примерно до 256 КБ символов. Если запрошенное смещение уже выброшено, ответ приходит с `truncated: true`, а `since` показывает, откуда текст реально начался.

`wait_for_text` ищет точное совпадение в первых 100000 символах после `since`. Регистр важен.

## Оркестрация уже запущенных агентов

`list_agents`, `ask_agent` и `ask_agents` работают с открытым окном. Они не запускают VibeTerm, Claude и Codex. Агент командной строки должен уже работать в своей панели.

Догадка о типе агента смотрит имя панели и хвост текущего вывода. Если там есть `codex`, это `codex`. Иначе, если есть `claude`, это `claude`. Иначе это обычная оболочка, `shell`.

`ask_agent` печатает задание и нажимает Enter. Дальше он читает только новый вывод.

- `untilText` - точная строка, после которой ожидание сразу заканчивается. Регистр важен.
- `quietMs` - сколько миллисекунд вывод должен не меняться, если конечная строка не задана. По умолчанию 4000, допустимо от 300 до 30000.
- `timeoutMs` - предел ожидания одной панели. По умолчанию 60000, не больше 120000.

В ответе `settled: true` значит, что ожидание закончилось по тишине или по `untilText`. Если `settled: false`, ответ модели ещё не собран. Тогда вызовите `read_output` и передайте `nextOffset` как `since`.

`ask_agents` отправляет одно задание нескольким панелям одновременно. Ответ - массив. У панели со сбоем в её элементе будет поле `error`, остальные элементы при этом остаются.

Полноэкранный интерфейс агента читается плохо: уже напечатанные строки не переписываются, когда программа двигает курсор вверх. Надёжнее обычный текстовый режим и известная конечная строка в `untilText`.

## Пример

1. Вызовите `list_panels` и запомните `id` нужной панели и `outputOffset`.
2. Вызовите `send_input` с `panelId`, текстом `Write-Output vibeterm-ok` и `submit: true`.
3. Вызовите `wait_for_text` с этим `panelId`, текстом `vibeterm-ok` и `since`, равным прежнему `outputOffset`.
4. Если команда зависла, вызовите `send_keys` с `keys` равным `ctrl+c`.

## HTTP-интерфейс

Базовый адрес берите из `panel-api.json`. Не подставляйте `localhost`: он может уйти на другой сетевой адрес, а сервер слушает только `127.0.0.1`.

Ко всем запросам нужен заголовок:

```text
Authorization: Bearer <token>
```

Тело запроса - JSON, не больше 256 КБ.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/v1/health` | Проверка, что интерфейс отвечает. Ответ: `{"ok":true}` |
| `GET /api/v1/panels` | Список |
| `POST /api/v1/panels` | Создать. Тело: `{"name":"Build","workingDirectory":"F:\\work"}` |
| `GET /api/v1/panels/{id}` | Одна панель |
| `DELETE /api/v1/panels/{id}` | Закрыть |
| `POST /api/v1/panels/{id}/select` | Выбрать |
| `POST /api/v1/panels/{id}/rename` | Тело: `{"name":"Logs"}` |
| `POST /api/v1/panels/{id}/input` | Тело: `{"text":"dir","submit":true}`. Если `submit` не передан, Enter не нажимается |
| `POST /api/v1/panels/{id}/keys` | Тело: `{"keys":"ctrl+c"}` |
| `GET /api/v1/panels/{id}/output?since=0&maxChars=16000` | Текст. `maxChars` от 1 до 100000 |
| `POST /api/v1/panels/{id}/wait` | Тело: `{"text":"PS ","since":0,"timeoutMs":5000}` |

Ответ с текстом выглядит так:

```json
{
  "id": 1,
  "since": 0,
  "nextOffset": 42,
  "text": "hello\n",
  "truncated": false
}
```

Ошибка выглядит так:

```json
{ "error": "panel not found" }
```

| Код | Когда |
| --- | --- |
| 401 | Нет ключа или ключ не тот |
| 400 | Неверный JSON, неизвестная клавиша, слишком длинный текст, нет каталога |
| 404 | Нет такой панели или пути |
| 409 | Панель ещё запускается или оболочка уже завершилась |
| 500 | Сбой внутри приложения. Текст исключения наружу не отдаётся |

Пример запроса из PowerShell. Подставьте свои `baseUrl` и `token` из файла.

```powershell
$endpoint = Get-Content "$env:APPDATA\VibeTerm\panel-api.json" | ConvertFrom-Json
$headers = @{ Authorization = "Bearer $($endpoint.token)" }
Invoke-RestMethod -Headers $headers -Uri "$($endpoint.baseUrl)/api/v1/panels"
```

## Проверка

Из корня репозитория:

```powershell
dotnet test .\VibeTerm.sln
```

Проверяются разбор текста терминала, локальный интерфейс и запуск MCP-сервера со списком инструментов.

Живая проверка с окном: запустите VibeTerm, дождитесь `panel-api.json`, запросите список панелей и отправьте в готовую панель `Write-Output` с заметной строкой. Затем прочитайте вывод и убедитесь, что строка есть. После этого закройте окно.
